---
term: Performance
summary: How fast a page becomes usable and stays responsive, measured against where the time actually goes rather than where it's assumed to go.
---

A slow page can lose time to JavaScript execution, layout and paint, network requests, third-party scripts, or genuinely expensive rendering — and the fix only helps if it targets the right one. Profiling before optimizing is the discipline this term is really pointing at: it is easy to see a sluggish React page and assume React is the bottleneck, reach for a caching hook like `useMemo` or render only the visible rows of a long list (virtualization), and measure no improvement because the actual cost was a synchronous third-party script blocking the main thread.

Browser DevTools' performance panel, not intuition, is the source of truth for where time goes. Google's Core Web Vitals give the practical targets most performance work is measured against today: how soon the main content appears (LCP), how quickly the page responds to a click or keypress (INP), and how much the layout jumps around while loading (CLS).
